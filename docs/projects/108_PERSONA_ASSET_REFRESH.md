**Status:** 🟢 Done (2026-09-03) — Strategy C implemented and approved.

## 1. The Executive Summary
**User Story:** As a prospective user landing on the Welcome page (or an existing user on `/login`), I want the six persona illustrations to look like one deliberate, cohesive art style so that MRT reads as a polished, intentional product rather than a set of mismatched stock-style avatars stitched together over time.
**Competitive Gap:** Persona-driven onboarding is a differentiator vs. generic sobriety trackers ("I Am Sober", "Reframe") — but only if the personas feel like a designed cast, not placeholder art. The current set has three competing illustration styles across six people; this closes that gap and gives MRT a distinctive, ownable visual identity (bold pop-art/halftone) instead of generic flat-cartoon icons.

## 3. Schema & Architecture 🗄️

**Source material (already in repo, not yet web-ready):**
`public/personas/Persona Headshots and Angles/mrt_<name>_{headshot,front_view,360_view}.png` — 18 files, 6 personas × 3 angles, ~2–3MB each, uncropped/uncompressed production renders. These are **inputs to be processed**, not final web assets — they must not be served from `public/` at full size.

**Pre-existing, never-implemented structure this refresh should finally satisfy:** `docs/PERSONAS.md`'s per-persona "Asset Metadata" sections have referenced `ASSETS.personas.<name>.full_body` and `ASSETS.personas.<name>.looking_left` since at least v2.1 — but `src/data/assets.ts` (auto-generated by `scripts/generate_asset_index.py`) has never actually contained those keys, only flat `<name>_headshot` / `<name>_bio` / `<name>.jpg` entries. The new `front_view` (full body) and `360_view` (3-pose turnaround, includes a left-profile pose) source images are a natural fit for finally implementing `full_body` and `looking_left` — this refresh should close that gap rather than perpetuate it.

**Target directory structure** (mirrors the nested-object shape `docs/projects/24_ASSET_ENGINE.md` originally specified but was never fully realized — current `assets.ts` is flat per-persona keys, not nested):
```
public/personas/
  david/headshot.webp
  david/full_body.webp
  david/looking_left.webp
  ... (×6 personas)
```
Restructuring from flat (`david_headshot.webp`) to nested (`david/headshot.webp`) is a **decision point for `/planning`**, not assumed here — it changes every call site (`ASSETS.personas.david_headshot` → `ASSETS.personas.david.headshot`) and touches `Welcome.tsx`, `Login.tsx`, and `docs/PERSONAS.md`'s own documented (if never-implemented) shape. Either the nested shape ships now (fulfilling the long-documented intent) or the flat convention is kept and `PERSONAS.md`'s Asset Metadata sections are corrected to match reality instead — `/planning` should weigh both as strategies.

**Bio card format — the actual open problem:** The current `*_bio.webp` files are pre-baked composite images (headshot + backstory text burned into the pixels by whatever tool made them) — and are dead code today (registered in `assets.ts`, referenced nowhere in `src/`). The new source set contains **no equivalent bio-card composites**, only headshot/body/turnaround art. This session has no image-generation tool available, so a byte-for-byte "new pop-art bio card" cannot be produced the way the old one was. The realistic path is converting the bio card from a pre-baked image into a **code-rendered component** (new pop-art headshot crop + a styled text panel built with Tailwind, matching the halftone/bold-outline palette) — this also directly solves the Maya/Jordan bio-content gap, since bio text can be authored without needing matching baked artwork. `/planning` should confirm this approach and design the component.

**Files needing updates:**
* `src/data/assets.ts` — regenerated via `python3 scripts/generate_asset_index.py` after source files are processed and placed (never hand-edited, per its own header).
* `src/pages/Welcome.tsx` — `PERSONA_CONTENT` array, `headshot:` fields (4 of 6 personas currently; decide whether to expand to all 6 or leave Maya/Jordan absent from this specific marketing carousel, which is itself an open product question, not an asset question).
* `src/pages/Login.tsx` — `PERSONAS` array currently hardcodes `/personas/<name>.jpg` (bypasses `ASSETS` entirely, and those jpgs are actually full bio-card composites mis-served as plain avatars). Needs to both switch to real headshot crops and route through `ASSETS` instead of hardcoded strings — a small pre-existing bug this refresh should fix in passing.
* `docs/PERSONAS.md` — Asset Metadata sections per persona, once the real key shape is decided (see above).
* Old files retired: `david|ned|lisa|walt_headshot.webp`, `*_bio.webp`, `*.jpg`, `maya|jordan_headshot.webp` — deletions, not silent overwrites; confirm nothing else references them first (already checked: only `assets.ts`, `Welcome.tsx`, `Login.tsx` do).

**No Firestore/db changes.**
